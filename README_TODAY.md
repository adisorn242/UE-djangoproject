# 🚀 คู่มือระบบสมาชิก (Authentication & Profile System)

สรุปการทำงานของไฟล์ต่างๆ ที่ได้พัฒนาในวันนี้ เพื่อใช้เป็นสื่อการสอนและแนวทางในการพัฒนาต่อยอด

---

## 📂 โครงสร้างไฟล์ที่สำคัญ

### 1. 🏗️ Models (`myapp/models.py`)
- **`class Profile`**: เป็นโมเดลที่ขยายข้อมูลผู้ใช้ (User) โดยใช้ `OneToOneField` เชื่อมกับโมเดล `User` หลักของ Django
  - เก็บข้อมูล: `fullname` (ชื่อเต็ม), `avatar` (รูปโปรไฟล์), `bio` (ประวัติย่อ), และ `website`
- **Signals (`post_save`)**: เป็นระบบ "ตัวดักจับเหตุการณ์" (Event Listener) ของ Django
  - **การทำงาน**:
    - **`post_save`**: คือสัญญาณที่จะส่งออกมาหลังจากที่มีข้อมูลถูกบันทึกลงฐานข้อมูลแล้ว
    - **`sender=User`**: ระบุว่าเราจะดักจับเหตุการณ์ที่เกิดขึ้นกับตาราง `User` เท่านั้น
    - **`create_user_profile`**: 
        - เมื่อมีการสมัครสมาชิกใหม่ (`created=True`) ระบบจะสั่งให้สร้าง (`Profile.objects.create`) ข้อมูลโปรไฟล์ที่ผูกกับ User คนนั้นทันที
        - *ประโยชน์*: ทำให้เราไม่ต้องเขียน Code สร้าง Profile ซ้ำๆ ในหน้าสมัครสมาชิก
    - **`save_user_profile`**: 
        - ทำหน้าที่บันทึกข้อมูล Profile (`instance.profile.save()`) ทุกครั้งที่มีการอัปเดตข้อมูล User 
        - *ประโยชน์*: ช่วยให้มั่นใจว่าข้อมูลทั้งสองตารางจะซิงค์ (Sync) กันเสมอ

### 2. 📝 Forms (`myapp/forms.py`)
- **`class UserRegisterForm`**: สืบทอดมาจาก `UserCreationForm` ของ Django
  - **การทำงาน**:
    - **Inheritance**: การสืบทอดจาก `UserCreationForm` ทำให้เราได้ระบบการสมัครสมาชิกพื้นฐาน (เช่น ช่องกรอกรหัสผ่าน 2 ช่อง และการตรวจสอบรหัสผ่าน) มาโดยไม่ต้องเขียนเอง
    - **Custom Field**: เราเพิ่ม `email = forms.EmailField(...)` เข้าไปเพราะในฟอร์มมาตรฐานของ Django จะไม่มีช่องอีเมลมาให้ในตอนสมัคร
    - **Meta Class**:
        - `model = User`: บอกว่าฟอร์มนี้ใช้สำหรับจัดการข้อมูลในตาราง `User`
        - `fields`: ระบุลำดับของช่องที่จะให้แสดงผล (ชื่อผู้ใช้ และ อีเมล)
        - `labels`: กำหนดชื่อเรียกหน้าช่องกรอกข้อมูลให้เป็นภาษาไทย เพื่อความสวยงามและเข้าใจง่าย

### 3. ⚙️ Views (`myapp/views.py`)
- **`register`**: จัดการการสมัครสมาชิก ตรวจสอบความถูกต้องของข้อมูล และแสดงข้อความ Success ด้วย `messages`
- **`login`**: ฟังก์ชันสำหรับเข้าสู่ระบบ โดยใช้ `AuthenticationForm` เพื่อตรวจสอบชื่อผู้ใช้และรหัสผ่าน
- **`logout`**: ฟังก์ชันสำหรับออกจากระบบ และเตะผู้ใช้ออกไปหน้าแรก
- **`profile`**: หน้าแสดงข้อมูลส่วนตัวของผู้ใช้ โดยมีการใช้ `@login_required` เพื่อป้องกันไม่ให้คนที่ไม่ล็อกอินแอบเข้ามาดู

### 4. 🌐 URLs (`myapp/urls.py`)
- กำหนดเส้นทาง (Path) ให้กับแต่ละฟังก์ชันใน Views:
  - `/register/` -> สมัครสมาชิก
  - `/login/` -> เข้าสู่ระบบ
  - `/logout/` -> ออกจากระบบ
  - `/profile/` -> หน้าข้อมูลส่วนตัว

### 5. 🎨 Templates (`myapp/templates/`)
- **`register.html` & `login.html`**: ใช้ดีไซน์แบบ Glassmorphism (โปร่งแสง) พร้อมฟอนต์ 'Prompt' และรองรับภาษาไทยเต็มรูปแบบ
- **`profile.html`**: หน้าแสดงข้อมูลส่วนตัว พร้อมรูปภาพและปุ่มจัดการข้อมูล
- **`logout.html`**: หน้าแจ้งเตือนหลังจากออกจากระบบ

### 6. 🖼️ Mockups (`myapp/templates/mockups/`)
- เป็นไฟล์ HTML แบบ **Static** (ไม่มี Code Python)
- เหมาะสำหรับการนำไปเปิดสอนเป็นตัวอย่างดีไซน์ หรือให้นักเรียนดูโครงสร้าง HTML/CSS เบื้องต้นก่อนจะใส่ Logic ของ Django

## 🧠 เจาะลึกการทำงานของ Views (Logic Explanation)

### 1. `register(request)` - ระบบสมัครสมาชิก
- **ตรวจสอบ Method**: เช็คว่าเป็น `POST` (ส่งข้อมูล) หรือไม่ ถ้าไม่ใช่ (เป็น `GET`) จะแสดงฟอร์มเปล่า
- **ตรวจสอบความถูกต้อง**: ใช้ `form.is_valid()` เพื่อเช็คว่ารหัสผ่านตรงกันไหม หรือชื่อผู้ใช้ซ้ำหรือไม่
- **การบันทึก**: เมื่อข้อมูลถูกต้องจะสั่ง `form.save()` เพื่อลงฐานข้อมูล
- **การแจ้งเตือน**: ใช้ `messages.success` เพื่อส่งข้อความ "สร้างบัญชีสำเร็จ" ไปแสดงผลในหน้าถัดไป
- **การส่งต่อ**: เมื่อเสร็จแล้วจะ `redirect` ไปยังหน้า `login` ทันที

### 2. `login(request)` - ระบบเข้าสู่ระบบ
- **AuthenticationForm**: ใช้ฟอร์มมาตรฐานของ Django ในการรับชื่อผู้ใช้และรหัสผ่าน
- **ตรวจสอบตัวตน**: `form.get_user()` จะดึงข้อมูลผู้ใช้ที่ตรวจสอบแล้วออกมา
- **การสั่ง Login**: ใช้ `auth_login(request, user)` เพื่อสร้าง Session ให้ผู้ใช้สามารถอยู่ในระบบได้
- **การส่งต่อ**: เมื่อล็อกอินสำเร็จจะพาไปหน้าแรก (`home`)

### 3. `logout(request)` - ระบบออกจากระบบ
- **การสั่ง Logout**: ใช้ `auth_logout(request)` เพื่อลบ Session ของผู้ใช้ทิ้ง
- **การส่งต่อ**: พาผู้ใช้กลับไปยังหน้าแรกเพื่อให้ระบบตรวจสอบสถานะใหม่

### 4. `profile(request)` - หน้าข้อมูลส่วนตัว
- **@login_required**: เป็น Decorator ที่สำคัญมาก ทำหน้าที่ "ล็อกประตู" หน้านี้ไว้ ถ้ายังไม่ได้ล็อกอิน ระบบจะเด้งไปหน้า Login อัตโนมัติ
- **การแสดงผล**: เมื่อผ่านประตูมาได้ จะดึงข้อมูล `Profile` ที่เชื่อมกับ `User` นั้นๆ มาแสดงผลในหน้า `profile.html`

## 🛠️ การตั้งค่าเพิ่มเติม (`settings.py`)
- **`LOGIN_REDIRECT_URL = '/'`**: เมื่อล็อกอินสำเร็จ ให้เด้งไปหน้าแรก
- **`LOGIN_URL = 'login'`**: ถ้าผู้ใช้พยายามเข้าหน้า Profile โดยไม่ได้ล็อกอิน ให้เด้งไปหน้า Login อัตโนมัติ
